# 07-模拟屏保真度与 CI 门禁

> 适用对象：`abbot/server/web/index.html`（模拟后台「真机画面」Tab）与 `abbot/firmware/`（真机固件）。
> 真相源：`abbot/doc/03-竖屏界面布局与交互规范.md`。

---

## 一、模拟屏的定位

模拟屏（`abbot/server/web/index.html` 的「真机画面」Tab）不是真机的截图、也不是原型稿，
它是**同一块 ST7796S 320×480 竖屏在浏览器里的第二个实现**（零构建单文件，canvas 逐页复现）。

它同时承担三个角色：

| 角色 | 说明 |
|---|---|
| 开发期真机替身 | 固件还在迭代时，没有板子也能看到「屏幕长什么样」，改 UI 不必烧录 |
| 端云契约验证器 | 用同一套页面结构去跑上报链路（心跳/天气/OTA），验证端云字段口径是否一致 |
| 长期并存的第二实现 | 它不会被「真机出来就删掉」——它是契约的活文档，能在没人拿板子时暴露漂移 |

真机固件仍然是唯一发布物；模拟屏是「同一份 UI 规范」的第二个实现。

---

## 二、保真度契约（硬规则）

**`doc/03` 是 UI 真相源。固件 C 代码与模拟屏 canvas 都是 `doc/03` 的实现，二者是平级的。**

由此得到一条不可协商的规则：

> 固件 UI 发生任何变化（新增/删除/改名页面、增删改设置项、改候选城市、改版本号），
> **必须在同一个批次里同步修改模拟屏**。两批之间不允许存在任何中间状态。

这条规则已经被人违反过，代价是模拟屏长期缺页：少 `PAGE_CITY`、少阅读子页
`PAGE_BOOK_MENU` / `PAGE_BOOK_TOC` / `PAGE_BOOK_JUMP`、少防沉迷锁屏 `PAGE_BOOK_LOCKED`、
少 `PAGE_OOBE`，且上报的 `fw_version` 写死 `'v1.0.3'` 而固件已经是 `1.0.1`。

人的记忆撑不住这条规则，所以它必须由机器来守。

## 三、校验脚本

### 位置与命令

```
abbot/tools/check_ui_fidelity.py
```

一条命令即可运行（只用 python3 标准库，无第三方依赖，不需要编译固件）：

```bash
# 在仓库根目录执行
python3 abbot/tools/check_ui_fidelity.py
```

可用参数覆盖两侧路径（CI 与本地对比临时副本时用）：

```bash
python3 abbot/tools/check_ui_fidelity.py \
  --firmware-root abbot/firmware \
  --simulator    abbot/server/web/index.html
```

### 检查项

| # | 检查项 | 固件侧真相源 | 模拟屏侧 |
|---|---|---|---|
| 1 | 页面集合 | `firmware/include/ui_router.h` 的 `PAGE_*` 枚举 | `PAGES.PAGE_*` 定义 |
| 2 | 设置页条目 | `firmware/src/ui/ui_pages.cpp` 的 `ui_build_settings()`（含「所在城市」项） | `PAGES.PAGE_SETTINGS` 的 `label` |
| 3 | 候选城市表 | `firmware/src/ui/ui_weather.c` 的 `kCities[]`（中文名 + 上报英文名） | 城市列表数据 |
| 4 | 固件版本 | `firmware/include/net_api.h` 的 `NET_FW_VERSION` | 上报的 `fw_version` |

比对口径：

- **页面集合**：枚举成员 vs 页面定义，双向差集（只在有差异时打印具体页面名）。
- **设置页条目**：按「能力槽位」比对（wifi / volume / backlight / ota / battery / about /
  focus / city / pair / clock），允许两侧文案不同（例如固件「屏幕亮度」vs 模拟屏「屏幕背光亮度」），
  但**能力条目必须一一对应**；文案差异单独作为提示列出，不会把门禁刷红。
- **候选城市表**：中文显示名与上报用的英文名分开比对，两边都要覆盖。模拟屏侧只认**明确的候选城市数组**
  （数组内至少 6 条、每条都能解析出中文名+英文地名），不靠变量名猜测，避免把手势数组之类的无关数组
  误判成城市表。支持两种写法：`{zh:'北京', en:'Beijing'}` 与 `['北京', 'Beijing']`。
- **固件版本**：两侧都去掉 `v` 前缀后比较。模拟屏侧既支持直接字面量 `fw_version:'1.0.1'`，
  也支持常量引用 `const FW_VERSION='1.0.1'; ... fw_version:FW_VERSION`（先解析出常量的字面量值再比对）。

### 退出码语义

| 退出码 | 含义 |
|---|---|
| `0` | 四项全部一致（PASS） |
| `1` | 存在差异（FAIL）——页面缺失/多余、设置项缺失/多余、城市表不一致、版本不一致 |

CI 门禁直接用退出码判定：**退出码 1 = 门禁红**。

### 解析策略：容错但诚实

脚本按结构块解析（枚举块、函数块、数组字面量），**不用正则去匹配整个 C 文件**。
模拟屏侧在扫描前会先剥离 JS 注释与正则字面量 —— 注释里的一个英文撇号就会让引号配对整体错位，
后续所有数组边界都会被解析成一整个大窗口。

一旦源文件格式变了导致某一项解析不出来，脚本会明确打印

```
[FAIL] <检查项> —— 无法解析该项: <原因>
```

并**计入 FAIL、退出码 1**。绝不允许静默跳过 —— 静默跳过等于门禁失效，比没有门禁更危险。

## 四、CI 门禁位置与触发时机

### 仓库结构事实（决定了门禁只能挂在 workspace 仓）

- 本仓（workspace 仓）唯一远端是 `GlacierFang/inksight`，`abbot/` 是它的子目录，
  仓根**原先没有** `.github/workflows/`。
- `abbot/firmware/` 的正式发布仓是**另一个仓库** `GlacierFang/abbot-firmware`
  （本机工作副本在 `/tmp/abbot-firmware`），那边**没有** `abbot/server/web/index.html`。
- 因此**不能**把校验步骤加进 `abbot/firmware/.github/workflows/build.yml`：
  那条流水线在另一个仓跑，模拟屏文件根本不存在，加了必然红。

### 门禁位置

**新建**：`.github/workflows/abbot-ui-fidelity.yml`（workspace 仓**根级**最小 workflow）

即 workspace 仓**根级**最小 workflow，只做一件事：checkout 后跑 `python3 abbot/tools/check_ui_fidelity.py`。
它不碰固件构建、不调模型、不烧录，秒级完成。

### 触发时机

- `push` 与 `pull_request`，并用 `paths` 过滤，只在以下路径变动时触发：
  - `abbot/firmware/**` —— 固件 UI 改了
  - `abbot/server/web/index.html` —— 模拟屏改了
  - `abbot/tools/check_ui_fidelity.py` —— 门禁本身改了
  - `.github/workflows/abbot-ui-fidelity.yml`
- 另有 `workflow_dispatch` 供手动触发。

效果：**只改固件不改模拟屏的 PR 会被这条 job 直接判红**——这正是契约要的效果。

> 门禁当前为绿（模拟屏已补齐，四项全过，退出码 0）。此后任何「只改固件 UI、不改模拟屏」的提交
> 都会把它打红。现在可以把本 job 设成 required check。

## 五、跨层风险提示

1. **模拟屏上报的城市字符串必须与固件完全一致。**
   固件的候选城市表 `kCities[]` 有两列：`zh` 给用户看（中文界面），`en` 才是**上报给服务端的值**
   （服务端拿它做地名解析）。模拟屏若上报中文名或别的英文写法，天气链路直接对不上。

2. **服务端 `read_weather_snapshot()` 在「缓存 city 与上报 city 不一致」时返回空天气。**
   见 `abbot/server/app/weather.py`：`cached_city` 与 `resolve_city(device_id)` 不一致（大小写不敏感比较）
   就直接 `return {}`。它不抛错、不记错日志，所以表现为「首页天气栏莫名其妙是空的」，
   排查成本很高。模拟屏与固件城市字符串一致，是这条链路的隐含前置条件。

3. **`fw_version` 会随心跳上报。** 写死版本号会让服务端/OTA 侧的版本判定与真实固件不符，
   所以它必须跟着 `NET_FW_VERSION` 一起变。
