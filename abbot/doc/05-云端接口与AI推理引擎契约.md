# 05-云端接口与AI推理引擎契约

## 1. 架构定位与核心原则

* **无状态算力网关（Stateless AI Gateway）**：依据 `Local-First` 架构原则，TF 卡是设备唯一真实数据源（详见 `04-无线网络OTA与本地存储契约.md`）。树莓派 4B 不维护重型双端同步数据库，仅承担**安全鉴权、多模态 AI 路由推理、云端 ASR/TTS 音频中转缓存、离线学科包加密打包**及**轻量 Web 管理控制台**职能。
* **模型与厂商解耦（配置驱动）**：服务端代码严禁绑定特定大模型厂商或单一计费套餐档位。所有文本推理、多模态视觉推理、语音识别（ASR）及语音合成（TTS）均通过 `config.yaml` 热切换（兼容 OpenAI 标准接口协议及主流语音接口），修改配置热重载即可无缝切换模型或升级能力。
* **域名路由与异常收敛**：所有端云通信均通过用户自有域名路由（支持内网穿透反向代理）。面对隧道抖动（`502/503`）或上游模型限流（`429`），服务端统一收敛为标准业务降级状态码，由设备端执行指数退避（`60s -> 2m -> 5m -> 10m`）并映射为温和中文引导语（详见 `03-竖屏界面布局与交互规范.md` 第四节）。

## 2. 树莓派 4B 服务端工程结构与部署规范

### 2.1 技术栈与运行资源约束
* **运行环境**：Python 3.10+、`FastAPI` + `Uvicorn`（单进程异步 Worker，常驻内存控制 `< 150MB`）。
* **进程守护**：通过 Linux `systemd` 注册系统服务（`study-gateway.service`），配置 `Restart=always` 实现断电来电自启与异常自愈。
* **文件安全权限**：部署及初始化时强制将 `.env`、`config.yaml`、`storage/devices.json` 权限设为 `0600`（仅属主可读写）。

## 3. 端云双向安全信封、下载 Token 与联调基准向量

### 3.1 密钥编码与双用途派生规范
* 首次配对成功时，网关下发 `device_secret` 为 **64 位小写十六进制字符串**（如 `"00112233445566778899aabbccddeeff0123456789abcdef0123456789abcdef"`），服务端与设备端均将其 `hex_decode` 为 **32 字节原始二进制密钥 `secret_bytes`**（`len == 32`）：
  * **HMAC 签名密钥**：使用完整的 `32 字节` `secret_bytes`；
  * **AES-128-CTR 加密密钥**：截取 `secret_bytes[0:16]`（前 16 字节）。

### 3.2 请求与响应双向鉴权规范（防重放 + 防篡改）
除 `POST /api/v1/pair` 与带短时签名 Token 的静态下载接口外，所有端云 API 必须严格执行以下双向签名：

1. **HTTP 请求头（设备 $\rightarrow$ 网关）**：
   * `X-Device-Id`: 设备芯片唯一标识（如 `esp32s3_a1b2c3d4`）
   * `X-Timestamp`: 当前 Unix 时间戳（十进制秒级字符串），网关校验 `|server_now - int(X-Timestamp)| <= 60`，超窗返回 `4001`；
   * `X-Signature`: 使用 `secret_bytes` 对拼装串计算 `HMAC-SHA256` 的 64 位小写十六进制字符串：
     `sign_str = f"{METHOD}\n{PATH}\n{X-Timestamp}\n{RAW_BODY_SHA256}"`
     其中 `PATH` 为不含域名的纯路径（如 `/api/v1/study/solve`），`RAW_BODY_SHA256` 为**原始 HTTP 请求体字节流**（若 `GET` 请求无 Body 则为空字节串的 SHA-256 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`）的小写十六进制摘要。
2. **应用层加密信封（双向通用）**：
   * 业务明文 UTF-8 JSON 字节流经 `AES-128-CTR`（16 字节随机 `IV`，大端序 128-bit 计数器递增）加密后，拼装为 `Base64(IV_16B + Ciphertext)`，放入顶层 JSON 信封 `{"payload": "<base64_str>"}` 中传输；网关返回标准响应信封 `{"code": 0, "msg": "ok", "payload": "<base64_str>"}`（错误响应无业务数据时 `payload` 为 `""`）。
3. **HTTP 响应头（网关 $\rightarrow$ 设备，沿用同次请求 `X-Timestamp` 防篡改）**：
   * 网关返回任何业务响应时，在 Response Header 中附带：
     `X-Resp-Signature = HMAC-SHA256(key=secret_bytes, msg=f"{REQ_X_TIMESTAMP}\n{RAW_RESP_BODY_SHA256}").hexdigest()`
   * 其中 `REQ_X_TIMESTAMP` 为**本次对应 HTTP 请求头中的 `X-Timestamp` 原值**；设备端在发起请求时暂存该 `X-Timestamp`，收到响应后先校验 `X-Resp-Signature` 与接收到的原始响应体字节流是否匹配，校验通过后再解密 `payload`。

### 3.3 短时签名下载 Token 规范（`/api/v1/content/download` 与 OTA `bin_url` 共用）
所有二进制文件下载（课表 `schedule.json`、学科包 `meta.json / cards.enc / index.idx`、电子书 `.txt / .toc`、TTS `.wav` 及 OTA 固件 `.bin`）统一通过 `/api/v1/content/download?token=<token>` 获取：
* **Token 构造公式**：
  * 明文载荷：`raw_token = f"{device_id}|{expire_ts}|{rel_path}"`（`expire_ts = now + 600`，有效期 `10 分钟`；`rel_path` 为 `storage/` 下的相对路径，如 `packs/m7_geo/cards.enc` 或 `ota/fw_v1.0.3.bin`）；
  * 签名摘要：`sig = HMAC-SHA256(key=secret_bytes, msg=raw_token.encode("utf-8")).hexdigest()`；
  * 最终 Token：`token = urlsafe_b64encode(f"{raw_token}|{sig}".encode("utf-8")).decode("ascii")`（去除末尾 `=` 填充或标准 URL-Safe Base64 均可，服务端兼容补齐）。
* **服务端校验与响应头**：解码后校验 `now <= int(expire_ts)`、路径白名单防穿越及 `HMAC` 签名一致（失败返回 `HTTP 403`）；响应头必须包含 `Content-Length` 与 `X-File-Sha256`（完整文件 64 位小写 SHA-256 摘要），设备端按流式接收并校验哈希。

### 3.4 AES-128-CTR 与 HMAC-SHA256 锁定联调测试向量
开发端云安全模块时，必须先用以下固定向量完成单元测试对齐（两端必须输出逐字节一致的结果）。

> **向量生成与校验规范（强制）**：
> 1. 本组向量由**权威标准实现**（服务端 `cryptography` / 固件 `mbedtls`）逐字节产出，两端各自复现同一组值即视为对齐；
> 2. 实施方必须**先用 NIST SP 800-38A F.5.1 CTR-AES128 官方向量自检自身实现**，确认 AES-CTR 分组与 128-bit 大端序计数器推进正确后，再核对本组向量；
> 3. 本组向量配有可执行验证脚本 `doc/verify/verify_envelope.py`，端到端覆盖「请求验签 → 信封解密回环 → 响应验签」，安全模块任何改动后必须重跑；
> 4. **严禁为了让测试变绿而反向修改实现** —— 实现与本组向量冲突时，一律以本组向量为准修正实现。

* **`device_secret` (Hex)**: `00112233445566778899aabbccddeeff0123456789abcdef0123456789abcdef`
* **AES-128 密钥 (前 16B Hex)**: `00112233445566778899aabbccddeeff`
* **固定测试 `IV` (16B Hex)**: `0102030405060708090a0b0c0d0e0f10`
* **明文 JSON**: `{"ping":1}`（10 字节 ASCII：`7b2270696e67223a317d`）
* **期望密文 (10B Hex)**: `c44759d703127191d6c9`
* **期望信封 `payload` (`Base64(IV + Ciphertext)`)**: `AQIDBAUGBwgJCgsMDQ4PEMRHWdcDEnGR1sk=`
* **局部块偏移解密测试向量（验证 `cards.enc` 第 `block_index = 2` 块按需解密）**：
  * 沿用同一 `AES-128` 密钥与 `IV_base` `0102030405060708090a0b0c0d0e0f10`；
  * 大端序 128-bit 推进 `block_index = 2` 后的计数器 `nonce_counter` (16B Hex): `0102030405060708090a0b0c0d0e0f12`；
  * 明文 `{"ping":1}`（10B Hex：`7b2270696e67223a317d`）在 `block_index = 2` 处的期望密文 (10B Hex): `41da37cc48e5aa3f8d06`
* **当 `METHOD="POST"`, `PATH="/api/v1/ping"`, `X-Timestamp="1795412000"`, `RAW_BODY='{"payload":"AQIDBAUGBwgJCgsMDQ4PEMRHWdcDEnGR1sk="}'` (50 字节 ASCII) 时**：
  * `RAW_BODY_SHA256`: `0ac4d1b2be7fff8b8d2fabfd520add4656718547d456b728ab3f0049244fee0a`
  * 期望请求签名 `X-Signature`: `e93d4a3e4aaeb49a2b413c5edfb7c7b877d9f7a85bf1d4e5c01fcdab7cf45b35`
* **当响应体 `RAW_RESP_BODY='{"code":0,"msg":"ok","payload":""}'` (34 字节 ASCII) 且 `REQ_X_TIMESTAMP="1795412000"` 时**：
  * `RAW_RESP_BODY_SHA256`: `5eaa24073527cf9b66a37318bd50123aac4d649814ea6d65281189b6bef49ef3`
  * 期望响应签名 `X-Resp-Signature`: `c4fc10efeec73e428b7e63bcb3777658e11a850ccf2a75047847771556f0ce3c`
* **空请求体 `SHA-256`（`GET` 或无 Body 场景）**: `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`

### 3.5 统一业务状态码表
* `0`: 请求成功
* `4001`: 签名校验失败、响应验签失败或时间戳偏差超 60 秒
* `4002`: 配对码无效或已过期（5 分钟有效期）
* `4003`: 云端语音识别（ASR）结果为空、录音过短（`< 0.5s`）或置信度过低
* `4290`: 上游大模型窗口限流或同设备并发锁繁忙
* `4291`: 今日深度导学配额已耗尽
* `5001`: 上游模型推理超时或异常（触发设备端离线收件箱暂存或稍后重试）

## 4. 云端语音链路（ASR + TTS）与防依赖教学引擎

### 4.1 云端 ASR 语音识别规范（`app/speech_engine.py`）
* **数据载荷边界**：设备端采集 `16000Hz / 16bit / Mono` 原始 PCM（最长 `10 秒` = `320KB`，编码为 Base64 后约 `427KB`）。设备在发送前先校验录音有效时长 `>= 0.5 秒`（`>= 16KB`）且非全静音，过短直接本地拦截不上传。
* **网关 ASR 处理**：网关在 `config.yaml` 中配置云端 ASR 接口（兼容 OpenAI `/v1/audio/transcriptions` 或主流语音识别 API，自动为原始 PCM 封装 44 字节 WAV 头后上传，设置 `10s` ASR 识别超时，匹配设备端 `20s` HTTP 总超时）。若识别返回空文本或异常，直接返回业务码 `4003`（不消耗后续大模型推理 Token）。
* **第一级指令成本说明**：语音唤醒调节音量/查课表等操作需经过云端 ASR 转写为文本后，在树莓派本地规则引擎命中第一级路由（零大模型推理消耗，仅消耗极低廉的短语音 ASR 额度）。

### 4.2 网关侧持久化配额仲裁与三级意图分流
1. **并发互斥锁**：服务端为每个 `device_id` 维护一个 `asyncio.Lock`，同一设备前一个推理请求未完成前拒绝并发请求（返回 `4290`）。
2. **网关侧配额持久化（`storage/quota.json` 原子写入与磁盘满降级）**：
   * 网关将每台设备的当日配额状态持久化写入 `storage/quota.json`：
     ```json
     {
       "esp32s3_a1b2c3d4": {
         "date": "2026-11-23",
         "used_count": 2,
         "charged_sessions": ["sess_1795412000", "sess_1795415600"]
       }
     }
     ```
   * **原子写、重启恢复与磁盘写满保护**：每次更新 `storage/quota.json` 必须先写入同目录 `quota.json.tmp` 并调用 `file.flush()` 与 `os.fsync(file.fileno())`，再通过 `os.replace("quota.json.tmp", "quota.json")` 原子替换，杜绝树莓派意外断电导致配额文件损坏。若树莓派磁盘空间耗尽导致写入 `quota.json.tmp` 失败，捕获 `OSError` 并删除残缺 `.tmp` 文件，打印 Error 日志告警，内存中继续维持当前进程内的配额与已扣费会话集合以保障教学服务不中断（若进程重启则以设备端上报的 `device_remaining_quota` 作为兜底基准）。网关启动时加载该文件；每次鉴权配额前比对服务器本地日期（`UTC+8`），若 `date != today` 则自动重置 `used_count = 0` 并清空 `charged_sessions`。
   * **防重复扣费规则**：设备每次新建拍题生成唯一 `solve_session_id`；同题内请求下一步提示（`hint_level = 1` 或 `2`）或追问该题时沿用同一 `solve_session_id`。若 `solve_session_id` 已在 `charged_sessions` 中，**直接放行且不再扣减配额**；否则先校验 `effective_remaining = min(device_remaining_quota, daily_quota - used_count)`，若 `<= 0` 直接返回业务码 **`4291`**；仅当模型首次成功返回解析（`code == 0` 且 `status != "NEED_DRAFT"`）后，将 `solve_session_id` 加入 `charged_sessions`、`used_count += 1` 并立即原子写回 `storage/quota.json`。
3. **三级意图分流矩阵**：
   * **第一级（本地规则直出，零 LLM 调用）**：
     * 音量/亮度调节 $\rightarrow$ 返回 `intent_type: "LOCAL_ACTION"` 与 `action_payload: {"action": "SET_VOLUME|SET_BRIGHTNESS", "delta": 1|-1, "value": 1..5}`；
     * 今日/明日课表查询 $\rightarrow$ 返回 `intent_type: "LOCAL_ACTION"` 与 `action_payload: {"action": "SHOW_SCHEDULE", "day": "today|tomorrow"}`，由设备端直接读取本地最新 `/sdcard/config/schedule.json` 渲染并播报（确保离线手动微调或未同步时仍以本地课表为准）；
     * 天气查询 $\rightarrow$ 读取 `storage/cache/weather.json`（过期则异步更新），直接返回 `intent_type: "WEATHER_REPLY"` 与 `reply_text`。
   * **第二级（轻量纯文本模型 `FAST_TEXT_MODEL`）**：
     * 匹配概念问答、单词查询，或基于当前翻卡上下文（`context.pack_id + context.card_id`）的语音追问——服务端直接从 `storage/packs/<pack_id>/source.json` 中检索对应 `card_id` 的明文题干、提示与解析注入上下文（若目标包无 `source.json` 则退化为纯文本自由问答）。
   * **第三级（多模态视觉模型 `VISION_REASON_MODEL`）**：
     * 拍题导学（`/api/v1/study/solve`），内置草稿痕迹初筛、阶梯拆解（`0/1/2`）、留白验算与费曼反问四条铁律 System Prompt。

### 4.3 防依赖教学脚手架 System Prompt 规范
服务端收到请求中的 `edu_stage` 与 `enrollment_year` 后，按 `04` 文档第 3.1 节确定性算法计算当前学段标签 `{grade_anchor}`（如“初中1年级上”或“通用进修”）；若请求中包含 `pcm_base64`，先调用 ASR 转写得到文本覆盖 `{user_voice_text}`，否则读取请求中的 `voice_text`（兼容字段），注入以下 System Prompt：

```text
你是一位克制、启发式的私人学习导师。当前学生处于【{grade_anchor}】阶段，严格把控知识点边界，绝不使用超纲定理。
你必须严格遵守以下四条教学铁律：
1. 【草稿痕迹初筛】：首先观察图片中题目旁是否有学生手写的演算、辅助线或圈画痕迹。如果卷面完全空白，且学生未提供有效语音思路（"{user_voice_text}"为空），你必须拒绝直接讲解，仅用一句话温和引导其先写出第一步想法或画出已知条件，输出 status="NEED_DRAFT"。
2. 【阶梯拆解（当前层级：{hint_level}/2）】：
   - 层级 0：仅点破题目考察的核心概念与第一步切入点，严禁给出公式代入和最终答案。
   - 层级 1：给出关键的中间转化步骤或辅助线思路，留出核心计算步骤让学生自己完成。
   - 层级 2：核对学生思路并给出完整清晰的逻辑梳理与结论。
3. 【留白验算】：在层级 0 和层级 1 的回复结尾，必须抛出一个具体的微问题让孩子口头回答（例如：“根据这个条件，你能算出 ∠A 是多少度吗？”）。
4. 【费曼反问】：当判定学生已经做对或进入层级 2 完结时，必须在结尾附带 1 句简短的“费曼反问”（例如：“如果把题干里的‘平行’改成‘相交’，结论还成立吗？”），验证其是否真正理解。
输出必须为严格 JSON：{"status": "NEED_DRAFT|HINTING|SOLVED", "speech_text": "用于语音播报的口语化短句(<=80字)", "display_markdown": "用于屏幕分步阅读的结构化解析", "feynman_question": "可选反问句"}
```

### 4.4 纯云端 TTS 引擎与静默降级
* **零本地合成**：严禁在树莓派运行本地 TTS 模型或爬虫脚本；统一调用 `config.yaml` 配置的云端 TTS API（默认 MiniMax Speech），强制请求输出 **`16000Hz / 16bit / Mono` WAV** 格式。
* **编码避坑**：MiniMax 非流式接口返回 `Hex` 编码字符串，后端必须使用 `bytes.fromhex()` 解码落盘（严禁误用 Base64 解码）。
* **缓存键与静默降级**：按 `tts_cache_key = md5(f"{provider}:{voice_id}:wav16k:{speech_text}")` 缓存至 `storage/cache/tts/<tts_cache_key>.wav`。若云端 TTS 超时（`4s` 硬超时）或限流，网关不报错，直接置 `has_audio: false` 下发纯文本，设备端自动播放本地 `ding.wav` 并展示解析卡片。

## 6. Web 管理控制台（ASCII 线框与 Admin 后端 API 契约）

### 6.1 前端工程与安全交互约束
1. **零构建单文件架构**：收敛为单个 `web/index.html`（原生 HTML5 + CSS3 + Vanilla JS），由 FastAPI 静态直出，最大宽度 `768px` 移动端优先响应式居中布局。
2. **安全鉴权、会话超时、CSRF 防护与密钥脱敏**：
   * 管理员登录后签发 `HttpOnly + SameSite=Strict` 会话 Cookie，服务端会话存储同时记录创建时间（`7 天`绝对过期）与最后活跃时间（**`2 小时`无操作闲置自动过期**）；
   * 所有 `/admin/api/*` 状态修改接口（`POST`）除校验会话 Cookie 外，强制校验请求头 `X-Requested-With: XMLHttpRequest`（前端 `fetch` 统一附带），阻断跨站请求伪造（CSRF）；
   * 所有 API Key 输入框默认显示掩码占位符（`sk-••••••••••••`），后端永不回显完整明文密钥。
