# 02-硬件抽象层与底层驱动契约

## 一、 开发环境与全局编译宏规范
* **开发框架**：PlatformIO + Arduino-ESP32 Core (`espressif32` 平台，基于 ESP-IDF 5.x 内核)。
* **板级配置 (`platformio.ini` 强制约束)**：
  * `board = esp32-s3-devkitc-1`
  * `board_build.arduino.memory_type = qio_opi`（**强制启用 8 线 OPI PSRAM**，否则 8MB PSRAM 无法识别）
  * `board_build.flash_size = 16MB`
  * `board_build.partitions = huge_app.csv`（为字库、LVGL 缓冲区与网络协议栈留足程序空间）
  * `build_flags = -DBOARD_HAS_PSRAM -DARDUINO_USB_MODE=1 -DARDUINO_USB_CDC_ON_BOOT=1`

## 二、 全局总线仲裁与内存分配铁律

### 2.1 I2C 总线互斥锁（防摄像头 SCCB 与电量计总线打架）
* `OV5640`（`GPIO 4/5`）与 `MAX17043`（`GPIO 4/5`）物理共享 `I2C_NUM_0`，总线频率统一锁定为 **`100kHz`**（标准模式，兼容长线抗干扰）。
* **全局互斥信号量**：系统初始化阶段必须创建全局互斥锁 `SemaphoreHandle_t g_i2c_bus_mutex = xSemaphoreCreateMutex();`。
* **调用红线**：任何读取 `MAX17043` 电量或触发 `OV5640` 对焦寄存器的操作，**必须**先通过 `xSemaphoreTake(g_i2c_bus_mutex, pdMS_TO_TICKS(100))` 获取锁，操作完毕后立即 `xSemaphoreGive`；拍照捕获帧数据期间严禁轮询电量计（电量计刷新周期强制拉长至 **`30 秒/次`**）。

### 2.2 OPI PSRAM 内存分配边界
* 所有大块动态内存（摄像头帧缓冲 `fb`、LVGL 双帧缓冲、10 秒 WAV 录音缓冲、HTTP 接收缓冲）**强制使用 `heap_caps_malloc(size, MALLOC_CAP_SPIRAM)`** 分配在 8MB OPI PSRAM 中。
* 内部 SRAM（512KB）严格保留给 FreeRTOS 任务栈、Wi-Fi/LWIP 协议栈底层缓冲区及 DMA 描述符。

## 三、 外设驱动模块接口与实测容错规范

### 3.1 `hal_display`（ST7796S 竖屏驱动与背光 PWM）
* **引脚定义**：`MOSI=45`, `SCLK=46`, `CS=44`, `DC=47`, `RST=21`, `BLK=48`。
* **驱动配置**：采用 `LovyanGFX`（推荐，DMA 刷新效率高于 TFT_eSPI），SPI 写时钟设为 **`40MHz`**，逻辑分辨率锁定为竖屏 **`320 × 480`**（`rotation = 0` 或 `2`，以实测排针朝向为准）。
* **背光控制**：`GPIO 48` 绑定 `LEDC` PWM 通道（`5kHz`, `8-bit` 分辨率），支持 5 档亮度调节（`0 / 50 / 110 / 180 / 255`），进入 `Light-Sleep` 前平滑淡出至 `0`。

### 3.2 `hal_camera`（OV5640 拍题与自动对焦驱动）
* **基础参数**：`XCLK = 12MHz`（降频至 12MHz 提升长排线与高频 SPI 共存时的抗干扰能力，消除画面绿条/花屏），输出格式 `PIXFORMAT_JPEG`，`jpeg_quality = 10`（高质量压缩），`fb_count = 1`，`fb_location = CAMERA_FB_IN_PSRAM`。
* **两级分辨率动态切换**：
  * **取景预览模式**：`FRAMESIZE_HVGA`（`480 × 320` 旋转显示或居中裁剪适应 `320 × 480` 竖屏取景框），帧率目标 `12~15 fps`。
  * **高清拍题抓拍模式**：触发快门后动态切换至 **`FRAMESIZE_UXGA`（`1600 × 1200`）**，丢弃切换后的前 `2` 帧缓冲（让自动曝光与白平衡稳定），抓取第 `3` 帧高质量 JPEG（单张约 `180KB ~ 320KB`）存入 PSRAM 并同步备份至 TF 卡 `/captures/` 目录，随后切回预览分辨率。
* **VCM 自动对焦与防阻塞超时**：
  * **AF 固件存储与加载策略**：`OV5640` VCM 自动对焦固件补丁（约 4KB 寄存器序列）必须以 `const uint8_t` 数组形式编译进程序固件 Flash，在开机摄像头初始化阶段通过 SCCB/I2C 总线写入摄像头寄存器；**严禁从 TF 卡动态读取加载补丁**，杜绝因未插卡或 TF 卡异常导致摄像头对焦失效。
  * 写入补丁后，触发单次自动对焦命令（`0x3022 = 0x03`），轮询状态寄存器 `0x3029`（需持 `g_i2c_bus_mutex`）。
  * **强制超时熔断**：轮询上限设为 **`1500ms`**，若超时仍未返回 `0x10`（对焦锁定），**立即终止等待并直接执行抓拍**，绝不允许对焦失败导致系统卡死。

### 3.3 `hal_audio`（`ICS43434 + MAX98357` 半双工 I2S 复用驱动）
* **引脚定义**：`BCLK/SCK=41`, `LRCLK/WS=42`, `DIN(功放)=14`, `SD(硅麦)=1`，统一挂载在 **`I2S_NUM_0`**。
* **严格半双工状态机（杜绝总线冲突与回声）**：
  * `AUDIO_IDLE`：卸载/停用 I2S DMA 通道，功放静音，降低功耗。
  * `AUDIO_RECORDING`：以 `I2S_MODE_MASTER | I2S_MODE_RX` 模式初始化 `I2S_NUM_0`，采样率 **`16000Hz`**，格式 **`I2S_COMM_FORMAT_STAND_I2S`（标准 Philips 飞利浦时序格式）**，通道槽宽 **`32-bit`**（右移 `16` 位提取高 `16-bit` 有效 PCM，单声道），在 PSRAM 预分配 `320KB` 环形/线性缓冲（硬上限 `10 秒`）。
    * **`ICS43434` 硅麦专属时序与防爆音保护**：每次切入 `AUDIO_RECORDING` 启动 DMA 后，**强制丢弃前 `30ms`（480 个采样点）的唤醒瞬态数据**，彻底消除 `ICS43434` 上电唤醒瞬间的“噗”声爆音与直流偏置漂移；若模块默认将 `L/R` 拉高，通过宏定义 `MIC_I2S_CHANNEL`（默认左声道 `I2S_CHANNEL_FMT_ONLY_LEFT`，可一键切 `ONLY_RIGHT`）适配。
  * `AUDIO_PLAYING`：录制结束或收到树莓派下发的 TTS 音频流后，**必须先调用 `i2s_driver_uninstall(I2S_NUM_0)` 彻底释放 RX 通道**，再以 `I2S_MODE_MASTER | I2S_MODE_TX` 重新初始化（`16000Hz` / `16-bit` / `Mono`），支持边接收 HTTP 分块音频流边写入 DMA 播放（流式首字播报）。
* **设备端合成提示音（不依赖任何音频资产文件）**：
  * `hal_audio_play_tone(uint16_t freq_hz, uint16_t duration_ms)` —— 在功放上直接推出指定频率的正弦音，**在音频任务里调用**（本函数是阻塞的，会占住 I2S 播放通道）；播完自行 `i2s_driver_uninstall` 回到 `AUDIO_IDLE`，否则后续录音会被半双工状态机拒绝。音量沿用 `hal_audio_set_volume` 的 `1~5` 档。
  * `hal_audio_request_tone(uint16_t freq_hz, uint16_t duration_ms)` —— **UI 核 → 音频任务的投递口**，队列满时返回 `HAL_ERR_NO_SPACE`；**UI 任务只投递不等待**，因此到点提示音**不阻塞界面**（番茄钟倒计时继续走）。
  * **为什么不用 `.wav` 资产**：提示音只需要一声固定频率的短音。为此单独开一块 LittleFS 分区要多占 Flash、多一条挂载与容错路径（挂载失败/损坏的降级分支），而合成一声正弦音只需几行 PCM 生成代码。

### 3.4 `hal_joystick`（双轴摇杆五向事件与防误触状态机）
* **采样硬件**：`VRx = GPIO 2 (ADC1_CH1)`，`VRy = GPIO 3 (ADC1_CH2)`，`SW = GPIO 0 (INPUT_PULLUP)`。
* **动态中点校准**：设备上电初始化后前 `300ms` 连续采样 `20` 次 `VRx / VRy` 原始值（此时摇杆处于静止归中状态），取平均值作为本次运行的零点基准 `center_x / center_y`（兼容摇杆机械回中误差，典型值约 `1950 ~ 2150`）。
* **滞回死区与方向判定（50Hz 定时器轮询）**：
  * 死区阈值：`±650`（12-bit ADC 满量程 `0~4095`），超出死区判定为 `UP / DOWN / LEFT / RIGHT`。
  * 首次触发后等待 **`400ms`** 进入连发模式（每 `150ms` 触发一次连续滚动事件），适配长解析文本顺滑翻页。
* **`SW` 按键消抖与按压归类（开机屏蔽 `500ms`）**：
  * **唯一裁定铁律**：按下时长与「短按 / 长按」的归类**只由 HAL 层本节裁定一次**，UI 层（`03` 文档浮层与页面状态机）严禁自行计时判定或另设阈值。
  * `EVENT_CLICK`（短按确定）：按下时长 `30ms ~ 600ms`（**不含 `600ms`**），于**释放瞬间**判定为短按。**不再等待「二次按下」的确认窗口**（原 `250ms` 双击判定窗口已废除，短按因此少一个可感知的延迟）。
  * `EVENT_LONG_PRESS_START` / `EVENT_LONG_PRESS_END`（长按退出）：持续按住 **`>= 600ms`** 时触发 `START`（armed 标志），松开瞬间触发 `END`；**UI 在 `END` 上执行退出动作**（按住不放不生效，避免误触即退）。
  * **不实现 `EVENT_DOUBLE_CLICK`**：真机只有一个中心键，双击依赖「两次按下的时序判定」，与长按阈值在同一时间轴上互相挤压 —— 想长按时系统正在等第二次按下，想双击时第一次按下可能已被判为长按，无法可靠区分。故固件**只产出短按与长按两类事件**。
  * **互斥保证**：短按窗口上界（`600ms` 不含）与长按下界（`600ms` 含）严格相接且不重叠 —— 按住不足 `600ms` 释放必判短按（够 `600ms` 未释放必判长按），**不存在既判短按又判长按的歧义区间**；`30ms` 以下的抖动按消抖丢弃，不产生任何事件。
  * **开机屏蔽 `500ms`**：仅指固件启动后屏蔽 `SW` 事件的静默窗口，与长按阈值无关，二者不可混用。

### 3.5 `hal_storage`（TF 卡 `SD_MMC` 挂载与断电保护）
* **引脚顺序强制规范**：调用 `SD_MMC.setPins(39, 38, 40)`（`CLK=39, CMD=38, D0=40`），以 `SD_MMC.begin("/sdcard", true)`（1-Bit 模式）挂载。
* **异常降级**：若未插 TF 卡或挂载失败，系统不崩溃，自动切换为“纯在线阅后即焚模式”（首页状态栏显示 `NO-SD` 警告图标，拍题解析仍可正常联网进行，仅跳过本地错题归档）。
* **自动循环清理**：每次写入新错题前检查剩余空间，若低于 **`100MB`**，自动删除 `/history/` 下最早创建的旧记录及对应图片。

### 3.6 `hal_power`（`MAX17043` 电量计与三级低功耗调度）
* **电量读取**：持 `g_i2c_bus_mutex` 读取 `MAX17043`（I2C 地址 `0x36`）的 `VCELL`（原始电压）与 `SOC`（百分比，钳位至 `0~100%`）。
* **状态机**：
  * **正常活跃态**：屏幕全亮，Wi-Fi 按需连接。
  * **无操作 `60 秒`**：背光平滑降至最低档（`PWM = 30`）。
  * **无操作 `180 秒`**：关闭背光（`PWM = 0`），关闭摄像头时钟，配置 `GPIO 0`（摇杆下压低电平唤醒）与 RTC 定时器唤醒（距离下一节整点课程前 5 分钟唤醒闹钟），进入 **`esp_light_sleep_start()`**。
  * **浅休眠唤醒外设恢复**：无论是 `GPIO 0` 按键唤醒还是 RTC 课程闹钟定时唤醒，退出 `Light-Sleep` 后因外设电源域掉电会导致 `SPI` 屏幕、`I2C` 总线及 `I2S` 音频状态丢失，**固件必须在业务弹窗渲染前重新执行上述外设总线与屏幕的硬件恢复初始化流程**，再恢复背光亮度并执行提醒弹窗或语音播报。
  * **低电保护**：当电池电压持续低于 **`3.40V`**（`SOC <= 5%`）时，屏幕弹出“电量耗尽，请充电”提示 `3 秒` 后强制进入深度睡眠（`esp_deep_sleep_start()`），保护锂电池不过放。


## 四、 FreeRTOS 双核任务划分与队列规范

> 本节补齐 `00` 文档地图中承诺但原文缺失的内容。所有划分均以「**界面永不阻塞**」为唯一原则。

### 4.1 双核硬划分（不可违背）

| 核 | 独占任务 | 职责 | 禁止事项 |
| :--- | :--- | :--- | :--- |
| **Core 1（界面核）** | `task_ui_fsm` | LVGL 渲染、页面路由状态机、手势仲裁、三层浮层优先级抢占、错误码查表渲染 | **严禁**执行任何阻塞式网络或 TF 卡 IO |
| **Core 1（界面核）** | `task_joystick` | `50Hz` 摇杆采样、死区滞回、短按/长按归类（见第 3.4 节） | 严禁把未归类事件直接抛给 UI 层自行判定 |
| **Core 0（IO 核）** | `task_net_worker` | Wi-Fi 异步扫描与连接、HTTP 请求与 TLS、加密业务请求收发、OTA 下载与写分区 | 严禁触碰 LVGL 对象 |
| **Core 0（IO 核）** | `task_camera` | 取景预览、AF 对焦（持 `g_i2c_bus_mutex`）、UXGA 抓拍 | 严禁在 Core 1 阻塞等待对焦 |
| **Core 0（IO 核）** | `task_audio` | I2S 半双工录音与 TTS 流式播放 | 严禁与 Core 1 同时占用 `I2S_NUM_0` |
| **Core 0（IO 核）** | `task_storage` | TF 卡读写、原子写入、目录遍历、空间回收 | 严禁在 Core 1 同步调用 |

* **依据**：`04` 文档第 1.1 节「在 Core 0 后台执行 `WiFi.scanNetworks(true)`，扫描期间绝不阻塞 Core 1 界面渲染与摇杆采样」。
* **双核协作铁律**：Core 0 产出的结果（网络应答、提示卡片、TTS 就绪）**必须经队列投递回 Core 1**，严禁 Core 0 直接调用 LVGL API。

### 4.2 跨核通信队列规范（严禁裸共享变量）

| 队列 | 元素类型 | 方向 | 长度 | 载荷要点 |
| :--- | :--- | :--- | :--- | :--- |
| `q_joystick_event` | `joystick_event_t` | 采样 → UI | `8` | 已完成消抖与归类的事件（方向 / CLICK / DBL_CLICK / LONG_START / LONG_END） |
| `q_ui_command` | `ui_command_t` | IO 核 → UI 核 | `16` | 网络应答、提示卡片、刷新页面等 UI 指令 |
| `q_photo_request` | `photo_request_t` | UI 核 → 相机任务 | `4` | 抓拍指令（含「边说边拍」标志与目标分辨率） |
| `q_audio_pcm` | `audio_pcm_chunk_t` | 录音 → 播放 | `8` | 16kHz / 16bit / Mono PCM 分块（总缓冲硬上限 `10 秒`） |
| `q_net_request` | `net_request_t` | UI 核 / 相机任务 → 网络任务 | `8` | **业务参数**（端点 op / 会话号 / 图像指针 / PCM），加签与加密在网络任务内完成；JPEG 所有权随请求转移，用完由网络任务释放 |
| `q_ui_command`（kind=2） | `ui_command_t` | 网络任务 → UI 核 | `16` | 云端应答：业务码 + 解密后的业务明文（**堆内存，所有权随队列转移给 UI 释放**）；业务明文本身不排队，只传指针与长度 |

* **互斥锁**：全局 `g_i2c_bus_mutex`（本文件第 2.1 节，摄像头与电量计共用 `I2C_NUM_0`）；TF 卡独占访问由 `task_storage` 单线程串行化，不再额外加锁。
* **Wi-Fi 的跨核交接（不占队列）**：Wi-Fi 的驱动调用（`scanNetworks` / `begin` / `status`）**一律在 Core 0 的 `task_net_worker` 里做**，
  UI 核（Core 1）只做两件事：提交请求（`net_wifi_request_scan` / `net_wifi_submit_connect`）与读状态。
  跨核数据用**双槽 + 序号**搬运（扫描结果槽、连接请求槽各一份，写方写完再翻序号，读方按序号取当前槽），
  不让读方读到写了一半的数据；Wi-Fi 密码只存在内存里，**不进日志**，连上之后才写 NVS。
* **内存铁律**：帧缓冲、LVGL 双缓冲、录音缓冲、HTTP 接收缓冲一律 `heap_caps_malloc(size, MALLOC_CAP_SPIRAM)`（本文件第 2.2 节）；FreeRTOS 各任务栈分配在内部 SRAM。

## 五、 14 条底层防线（跨模块不可协商清单）

> 以下 14 条为全机不可协商的底线行为，每条均已在既有契约中有出处，此处仅做**汇总与交叉引用**，不新增行为。

| # | 防线 | 规范出处 |
| :---: | :--- | :--- |
| 1 | I2C 总线互斥：摄像头 SCCB 与电量计共用 `I2C_NUM_0`，所有访问持 `g_i2c_bus_mutex`（`100ms` 超时），拍照期间禁轮询电量 | 本文件 2.1 |
| 2 | 大块内存只用 OPI PSRAM：帧缓冲 / LVGL 缓冲 / 录音缓冲 / HTTP 缓冲走 `MALLOC_CAP_SPIRAM`，内部 SRAM 仅留给任务栈与协议栈 | 本文件 2.2 |
| 3 | 摇杆中点动态校准：开机 `300ms` 内连采 `20` 次取均值作零点，死区 `±650` 滞回判定 | 本文件 3.4 |
| 4 | 按压归类唯一裁定：短按 `< 600ms`、长按 `>= 600ms` 互斥无歧义，UI 层不得另设阈值；**固件不产出双击事件** | 本文件 3.4 |
| 5 | I2S 半双工独占 + 录音首 `30ms` 瞬态丢弃：播放前必须 `i2s_driver_uninstall` 释放 RX | 本文件 3.3 |
| 6 | AF 超时熔断：VCM 对焦轮询上限 `1500ms`，超时立即抓拍，绝不卡死 | 本文件 3.2 |
| 7 | 低电分级保护：`< 3.40V`（`SOC <= 5%`）弹窗 `3 秒` 后强制深度睡眠 | 本文件 3.6 |
| 8 | 浅休眠唤醒后外设重初始化：退 `Light-Sleep` 后必须重建 SPI 屏、I2C、I2S 状态再渲染 | 本文件 3.6 |
| 9 | TF 卡掉卡降级：不崩溃，切「纯在线阅后即焚模式」，仅跳过本地归档 | 本文件 3.5 |
| 10 | 原子写入四步 + 写满不覆盖：`.tmp` → `flush()` → 校验长度 → `.bak` → 重命名 | `04` 第 2.3 节 |
| 11 | UTF-8 字节边界对齐：偏移落在 `(byte & 0xC0) == 0x80` 时必须向前对齐到字符首字节 | `07` 第 3 节 |

## 六、 `hal_interfaces.h` 统一接口签名（HAL 层唯一对外契约）

> 固件内**任何**模块都只能经下列签名访问 HAL，**严禁直接调用 `Wire` / `SD_MMC` / `i2s_driver_*` / `esp_camera_*` 等底层 API**（唯一例外：`hal_storage` 与 `hal_audio` 的实现文件自身）。

```cpp
#pragma once
#include <Arduino.h>
#include <stddef.h>
#include <stdint.h>

#ifdef __cplusplus
extern "C" {
#endif

/* ---------- 通用返回码 ---------- */
typedef enum {
    HAL_OK              = 0,
    HAL_ERR_INVALID     = -1,   // 参数非法
    HAL_ERR_TIMEOUT     = -2,   // 超时（含 AF 对焦熔断）
    HAL_ERR_IO          = -3,   // 底层总线 / SD 读写失败
    HAL_ERR_NOT_FOUND   = -4,   // 文件或目标不存在
    HAL_ERR_NO_SPACE    = -5,   // 空间不足（原子写入失败时保留原文件）
    HAL_ERR_UNSUPPORTED = -6,   // 该设备/状态不支持（如无 TF 卡）
} hal_status_t;

/* ---------- hal_storage：TF 卡存储（SD_MMC 1-Bit） ---------- */
hal_status_t hal_storage_init_and_scaffold(void);                 // 挂载 + 空白卡自愈建全套目录
hal_status_t hal_storage_get_file_size(const char *path, uint32_t *out_size);
hal_status_t hal_storage_read_range(const char *path, uint32_t offset,
                                    uint8_t *buf, uint32_t len, uint32_t *out_read);
hal_status_t hal_storage_read_text(const char *path, char *buf, uint32_t max_len, uint32_t *out_len);
hal_status_t hal_storage_atomic_write_text(const char *path, const char *text, uint32_t len);
hal_status_t hal_storage_list_files(const char *dir_path, void (*cb)(const char *name, void *ctx), void *ctx);
hal_status_t hal_storage_delete_file(const char *path);
hal_status_t hal_storage_get_dir_usage(const char *dir_path, uint64_t *out_bytes);
hal_status_t hal_storage_get_file_mtime(const char *path, uint32_t *out_epoch);
bool        hal_storage_is_mounted(void);

/* ---------- hal_display：ST7796S 竖屏 + 背光 PWM ---------- */
hal_status_t hal_display_init(void);
hal_status_t hal_display_flush(void);
hal_status_t hal_display_set_backlight(uint8_t level);             // 0~5 档
uint8_t     hal_display_get_backlight(void);

/* ---------- hal_camera：OV5640 拍题 ---------- */
hal_status_t hal_camera_init(void);
hal_status_t hal_camera_start_preview(void);                        // FRAMESIZE_HVGA
hal_status_t hal_camera_capture_jpeg(uint8_t **out_jpg, size_t *out_len);  // 切 UXGA 抓拍，含 1500ms AF 熔断
hal_status_t hal_camera_stop_preview(void);

/* ---------- hal_photo：拍题抓拍请求（UI 核 → 相机任务） ---------- */
/**
 * 提交一次抓拍请求（投递到 `q_photo_request`，doc/02 §4.2 队列表已定的方向）。
 * `session_id` 是本题会话号（doc/05 §5.1：同题追问沿用同一个），可传 NULL。
 * 队列满时返回 `HAL_ERR_NO_SPACE`，由 UI 层给出温和中文提示。
 */
hal_status_t hal_photo_request_submit(const char *session_id, uint8_t want_uxga, uint8_t with_voice);

/* ---------- hal_audio：ICS43434 + MAX98357 半双工 I2S ---------- */
hal_status_t hal_audio_init(void);
hal_status_t hal_audio_start_record(void);                         // 16kHz/16bit/Mono，丢弃首 30ms
hal_status_t hal_audio_stop_record(void);
hal_status_t hal_audio_play_wav_file(const char *path);            // 校验 RIFF 头，跳过 44 字节
hal_status_t hal_audio_set_volume(uint8_t level);                  // 1~5 档

/* ---------- hal_joystick：双轴摇杆五向事件 ---------- */
hal_status_t hal_joystick_init(void);                              // 开机 300ms 中点校准
hal_status_t hal_joystick_poll(void);                              // 50Hz 调用，完成消抖与归类后投递队列

/* ---------- hal_power：MAX17043 电量计与低功耗 ---------- */
hal_status_t hal_power_init(void);
hal_status_t hal_power_read_battery(float *out_volts, uint8_t *out_soc);  // 持 g_i2c_bus_mutex
hal_status_t hal_power_enter_light_sleep(void);                    // GPIO0 / RTC 闹钟唤醒
hal_status_t hal_power_enter_deep_sleep(void);

/* ---------- 休眠唤醒后的外设恢复（02 第 3.6 节强制） ---------- */
hal_status_t hal_recover_after_sleep(void);                        // 重建 SPI 屏 / I2C / I2S 状态

#ifdef __cplusplus
}
#endif
```

* **实现约束**：`hal_camera` 内置 `const uint8_t` OV5640 VCM 自动对焦固件数组（严禁从 TF 卡动态加载）；`hal_audio` 实现严格半双工状态机与 `MIC_I2S_CHANNEL` 声道切换宏；`hal_power` 负责 `Light-Sleep` 唤醒后的外设恢复编排。
* **错误映射**：HAL 层只返回 `hal_status_t` 语义码，**严禁在 HAL 内拼装任何面向用户的中文提示文案**；所有面向用户的文案一律经 `03` 文档第四节的 `ui_show_friendly_error(ErrorCode)` 查表渲染。
