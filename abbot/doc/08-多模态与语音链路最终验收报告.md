## 二、模型与端点矩阵（实测有效）

| 能力 | 端点 | 模型 | 说明 |
| :--- | :--- | :--- | :--- |
| 文本 | `/v1/text/chatcompletion_v2` | `MiniMax-M2.5` | 也可走 `/v1/chat/completions` |
| 视觉 | `/v1/text/chatcompletion_v2` | `MiniMax-M3` | **该服务商没有独立视觉模型**（VL 系列已下架），视觉能力由 M3 / M3.1-Flash 原生承担；视觉**必须**走 `chatcompletion_v2` |
| ASR | `/v1/speech_to_text` | `asr-1.0` | 下划线不是斜杠；`multipart/form-data`；语言提示走 `language` 请求头 |
| TTS | `/v1/t2a_v2` | `speech-02-hd` + `male-qn-qingse` | 返回 Hex 字符串，按 `response_format: hex` 解码 |

**视觉能力归属实测表：**

| 模型 | 实测结论 |
| :--- | :--- |
| `MiniMax-M3` | ✅ 拍题端到端可用（照片 → 严格 JSON → `NEED_DRAFT`），**生产在用** |
| `MiniMax-M3.1-Flash` | ✅ HTTP 200 / `base_resp.status_code=0`，描述具体到画面位置，与原图核对完全吻合 |
| `MiniMax-M2.5` / `MiniMax-M2.7` | ❌ 一律回「我没有看到图片。」——纯文本模型，对图片无视觉能力 |
| `MiniMax-VL-01` 等 VL 系列 | `base_resp.status_code=2069`，已下架 |

**必须记住的陷阱：** 模型下线或参数错误时接口**仍返回 HTTP 200**，错误码在 body 的 `base_resp.status_code` 里，`2069` = 模型已下架。只看 HTTP 状态码会把「模型没了」误判成「内容为空」。

## 三、实测结论（每条都可复现）

| 场景 | 链路 | 实测结果 |
| :--- | :--- | :--- |
| 拍题（视觉） | 真实习题照片 → M3 → 严格 JSON | `status=SOLVED` + 逐题分步 `display_markdown` + 费曼反问，`has_audio=true`，配额 10→9 正确扣减 |
| 拍题（反向用例） | 真实照片（照片里没有题目文字） | `status=NEED_DRAFT` —— 模型正确地要求学生先写第一步，而不是编造答案 |
| 语音（ASR → 模型 → TTS） | 真实中文语音 → `asr-1.0` → 模型 → `speech-02-hd` | 转写正确 → 模型答出求根公式推导，`has_audio=true` |
| 播报（TTS） | `/v1/t2a_v2` | 音频落盘 `server/storage/cache/tts/<key>.wav`，`audio_url` 走签名下载通道；设备端格式一致（16000Hz / 1ch / 16bit） |
| 全链路 | `server/cli_sim.py --all` | **六步全 PASS**：ping / 配对 / 拍题 / 语音 / 心跳 / OTA |
| 端云信封 | `doc/verify/verify_envelope.py` + `server/tests/test_security_vectors.py` | 请求验签、信封解密回环、响应验签全 PASS；12 项契约向量全 PASS |

**判定「视觉真的跑了」的方法（踩过的坑）：** 最初用一张 294 字节的纯色几何图测视觉，M3 答「红色」看起来像通了 —— 实际是那张图触发了内容审核、图像被静默剥离，模型是猜的。**图片被审核拦下时上游返回 200 + 正常回复，不会报错。** 必须换真实照片验证。

## 四、HTTPS 边界（明确不在范围内）

- **abbot 外网入口保持明文 HTTP** —— `http://ruohan.site/abbot/`。这是已拍板多次的决策，**不在本次验收范围内**，也不作为风险上报。
- **MiniMax 官方 API 仍走 `https://api.minimaxi.com`** —— 服务商侧要求，与上述决策无关，不受其约束。
- 设备侧请求签名格式固定为 `METHOD\nPATH\nX-Timestamp\nRAW_BODY_SHA256`（`PATH` 不含域名、query string 和 `/abbot` 前缀）；设备密钥、HMAC 签名、AES-128-CTR 信封全部留在服务端，**密钥不回传浏览器**。

## 六、结论

1. **云端真实模型链路可用**，Phase 1 无硬件阶段 DoD 全部关闭；固件侧编译链路另行由 GitHub Actions 闭环（见 `ALIGN-NOTES` §9.13）。
2. **端云协议与实现逐字节一致**，契约向量与信封回环全 PASS。
3. **模型归属与下线陷阱已固化为规则**：视觉走 `chatcompletion_v2` + M3；下线看 `base_resp.status_code`，不看 HTTP 状态码。
4. **真机行为未验收**，等硬件到位后按逐像素、逐交互黄金样补做。
