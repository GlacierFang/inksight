# 端到端自检与上游故障排查

本文档记录 `server/tests/test_e2e_flow.py` 的跑法，以及**真实服务商链路**上最常见的两类故障。
适用对象：改了 `app/router_ai.py` / `app/speech_engine.py` / 上游模型配置之后。

---

## 1. 跑法

```bash
cd abbot
./.venv/bin/python server/tests/test_e2e_flow.py --base http://127.0.0.1:18843
```

- 网关必须已起：`systemctl --user restart openclaw-abbot.service`
- 末尾会打印 `RESULT: ALL PASS — N 项端到端检查通过`，或列出未通过项名。
- 测试**会真的调 MiniMax**（文本 + 视觉 + ASR + TTS），跑一次消耗一次额度。
- 测试自身幂等：开局会调 `/admin/api/quota/reset` 把当日账本清零。

## 2. 故障类型 A：上游临时性错误（最常见）

**症状**：拍题导学返回 `code=5001`，文案「云端有点忙，稍后再试一次」；
连带「剩余配额与服务端账本一致」也失败（服务端显示 10，期望 9）。

**根因**：MiniMax 集群繁忙时返回 **HTTP 529**，body 是

```json
{"type":"error","error":{"type":"overloaded_error",
 "message":"当前服务集群负载较高，请稍后重试，感谢您的耐心等待。 (2064)"}}
```

**为什么难查**：529 只出现在上游一次抖动里，直连探测往往又是 200，容易误判成"偶发"。
而且 5001 会把真实错误吞掉 —— `err()` 只回温和文案，细节只在服务端日志里，
而用户级 systemd 服务常常没有可用的 journal。

**挖出真实错误的办法**：在**进程内**直接调 `RouterAI.solve()`，绕开 HTTP 层，
用 monkeypatch 记录 `httpx.Client.post` 的请求/响应。请求体里的 `image_url` 要截断，
否则几百 KB 的 base64 会淹没输出。

**修法（已落地）**：`app/router_ai.py` 的 `_post_upstream()` 对
`429 / 500 / 502 / 503 / 504 / 529` 按退避重试，默认 2 次、2 秒
（配置项 `ai.max_retries` / `ai.retry_backoff_seconds`）。
**4xx 一律不重试** —— 鉴权、参数、内容审核类错误重试只是浪费配额和时间。

## 3. 故障类型 B：模型输入不合规

**症状**：同样是 5001，但重试也不管用。

**已见两例**：

| 上游返回 | 原因 |
|---|---|
| `base_resp=2013 invalid image content: decode image config` | 图片不是真 JPEG/PNG。e2e 曾用 `b"\xff\xd8\xff\xe0fake-jpeg-for-e2e"` 这种伪字节，被拒。 |
| HTTP 200 但 `content` 为空 | 图片被内容审核静默剥离 —— 模型只会回「我没有看到图片」。不会报错。 |

**修法**：e2e 改用真题图 `server/tests/assets/solve_sample.jpg`（PIL 生成的
320x200 题目图「2x + 7 = 19」）。**任何**走视觉链路的联调都必须用真图。

## 4. 铁律与 mock 的层级判定不一致（易误判为代码 bug）

04 教学铁律 1 规定：**卷面空白 + 学生未提供有效语音思路 → `NEED_DRAFT`**，
且**任何层级都适用**（层级 0/1/2 都先过这道初筛）。

而 `app/router_ai.py` 的 `_mock_vision()` 早期是按 `hint_level` 判
`SOLVED / HINTING / NEED_DRAFT` 的 —— 两者不等价。后果：

- `ai.provider: mock` 时测试全绿（mock 层级 1 直接给 HINTING）
- 换成真实模型后，干净的题面 + 空 `voice_text` 在**所有**层级都回 NEED_DRAFT
  → 不扣费 → 配额断言挂

**判据**：拍题返回 `NEED_DRAFT` 而测试期望扣费时，先看**是否给了 `voice_text`**。
真机上学生先开口说思路才会进入讲解档，这一条必须体现在测试请求里。

## 5. 端到端测试当前覆盖（36 项）

1. 网关自检（ping 信封） 2. 配对取 device_secret 3. 配额账本幂等清零
4. 拍题阶梯 0：验签 / HTTP 200 / code=0 / 四字段齐全 / status 枚举 / **NEED_DRAFT 不扣费**
5. 拍题阶梯 1：HINTING/SOLVED + **首次成功扣 1 次**
6. 同题追问（同 `solve_session_id`）：**不重复扣费**
7. 语音追问：HTTP 200 / 业务码 / **错误文案无技术术语**
8. 心跳同步：weather / pending_packs / pending_books / effective_remaining_quota / **账本一致**
9. 固件升级检查：has_update / latest_ver / sha256 / size / changelog
10. 未配对设备被拒 + 拒绝文案温和
