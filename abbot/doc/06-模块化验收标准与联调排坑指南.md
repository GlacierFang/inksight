## 二、 分阶段研发任务拆解与模块边界

### Phase 1：树莓派 4B 云端网关服务端（无硬件即可 100% 完工）
* **目录边界**：`server/`（Python 3.10+ / FastAPI / Uvicorn；持久化仅用 `05` 契约第 2.2 节规定的 `storage/*.json` 原子写文件，**不引入关系型数据库**，以严守 `05` 第 1 节「无状态算力网关」铁律）。
* **核心交付物**（文件名与 `05` 契约第 2.2 节 `app/` 目录树严格一致）：
  1. `server/app/main.py`：FastAPI 入口、全局异常处理、静态页面挂载；路由层严格实现 `05` 契约第 5 节规定的全部 RESTful API 端点、统一响应信封（`{code, msg, payload}`）与错误码映射；
  2. `server/app/config.py`：`config.yaml` 加载与热重载；模型、ASR、TTS、配额、OTA 策略一律由此配置，严禁代码硬编码厂商或模型名；
  3. `server/app/security.py`：双向 HMAC-SHA256 验签、AES-128-CTR 加解密、下载 Token 签发与校验（须通过 `05` 第 3.4 节向量组与 `doc/verify/verify_envelope.py`）；
  4. `server/app/router_ai.py`：三级意图分流、每设备 `asyncio.Lock` 并发锁、会话级配额持久化仲裁与 `05` 第 4.3 节防依赖教学 System Prompt 注入；
  5. `server/app/speech_engine.py`：纯云端 ASR 识别与纯云端 TTS 合成、Hex 解码落盘（**严禁误用 Base64 解码**）、MD5 缓存池；
  6. `server/app/storage.py`：`storage/` 目录持久化层 —— `devices.json`、`quota.json`、`schedules/latest.json`、`packs/`、`books/`、`ota/`、`cache/`；全部写入执行 `05` 第 4.2 节「写 `.tmp` → `flush()` → `os.fsync()` → `os.replace()`」原子替换协议，磁盘写满时捕获 `OSError`、删除残缺 `.tmp` 并保持进程内状态可用；
  7. `server/app/pack_builder.py`：原始文本 → 结构化 `source.json` → AES-128 加密 `cards.enc` + `index.idx`（含 `IDX1` 文件头与 CRC32）；
  8. `server/app/book_cleaner.py`：**零 AI 调用**的纯本地电子书清洗（`.epub` / `.pdf` / `.docx` / `.txt` → 标准 UTF-8 `.txt` + `.toc`）；
  9. `server/app/ota_manager.py`：固件魔数与 SHA-256 校验、多版本仓库、灰度白名单与熔断控制；
  10. `server/cli_sim.py`（**内置控制台设备模拟器**）：轻量级命令行交互脚本，直接在终端模拟 ESP32 设备发起拍题图片上传、长按语音追问音频上传、课表拉取与设备状态上报，打印校验返回的结构化 JSON 与音频流落盘结果。

### Phase 2：ESP32-S3 固件工程骨架与 HAL 驱动层（实物到位前完成编译闭环）
* **目录边界**：`firmware/platformio.ini`、`firmware/src/hal/`、`firmware/include/board_config.h`。
* **核心交付物**：
  1. `platformio.ini` 与分区配置：锁定 `qio_opi` 8 线 OPI PSRAM、`16MB Flash`、`huge_app.csv`；
  2. `board_config.h`：将 `01` 契约确定的全部 GPIO 引脚、I2C 地址（`0x36`）、SPI 频率（`40MHz`）与 `XCLK`（`12MHz`）固化为只读常量宏；
  3. 六大 HAL 独立模块（`hal_display`、`hal_camera`、`hal_audio`、`hal_joystick`、`hal_storage`、`hal_power`）：
     * `hal_camera` 内置 `const uint8_t` OV5640 VCM 自动对焦固件数组与 `1500ms` 超时熔断；
     * `hal_audio` 实现 `ICS43434 + MAX98357` 严格半双工状态机（Philips 标准 I2S 格式、丢弃录音前 `30ms` 唤醒瞬态数据、支持 `MIC_I2S_CHANNEL` 声道切换宏）；
     * `hal_power` 实现 `Light-Sleep` 唤醒（GPIO0 / RTC 课表闹钟）后的 SPI 屏幕、I2C 与 I2S 外设重初始化恢复逻辑。

### Phase 3：ESP32-S3 交互状态机、LVGL 竖屏 UI 与本地存储
* **目录边界**：`firmware/src/app/`、`firmware/src/ui/`、`firmware/src/net/`。
* **核心交付物**：
  1. 裁剪版中文字库（常用学习汉字子集）与 `320 × 480` 竖屏 LVGL 界面（首页仪表盘、取景框与对焦框叠加层、4 段式阶梯解析阅读器、录音波形浮层、历史错题列表、课表提醒弹窗）；
  2. 五向摇杆事件总线与页面路由状态机（短按确定、长按退出、四向导航与上下翻页连发；**不实现双击事件**，语音由操作菜单进入）；
  3. TF 卡 `/history/` 错题本地 JSON + JPEG 归档与 `100MB` 剩余空间自动滚动清理机制；
  4. HTTP 客户端（全部大缓冲分配在 `MALLOC_CAP_SPIRAM`），实现拍题上传、语音流式播报边下边播与幂等重试。

### Phase 4：端云真机联合调试与整机装配
* **前置条件**：硬件实物到位并按 `01` 契约完成免焊杜邦线插接与声学物理隔离装配。

## 四、 联调排坑指南（2026-11-24 实战沉淀）

### 4.1 浏览器没有麦克风，但 Chromium 能喂真音频
headless 验收要覆盖「真机麦克风 → PCM」这一段时，用 Chromium 的假音频设备代替物理麦克风：

```bash
chromium --headless=new \
  --use-fake-device-for-media-stream \
  --use-file-for-fake-audio-capture=<真实中文语音.wav> \
  --use-fake-ui-for-media-stream \
  --autoplay-policy=no-user-gesture-required ...
```

三个必踩的坑：① **必须先导航到 `127.0.0.1`** —— `about:blank` 不是安全上下文，`navigator.mediaDevices` 为 `undefined`；② **chromium 不能跨 exec 存活**（`setsid nohup &` 会随 shell 退出被杀，表现为 `ECONNREFUSED`），要让验收脚本自己 spawn、自己收尾；③ **CDP `Network.getResponseBody` 在本场景返回 null**，抓响应体不可靠 —— 改用 `Network.requestWillBeSent` 取请求体 + 服务端侧取证（TTS 缓存是否新增、生产 `transcribe()` 的转写结果）。

> **注意（2026-11-24 补记）：** 上述第 ③ 条正是后来那轮“假麦克风”验收拿到 `17 PASS / 3 FAIL` 的成因 —— 3 个失败项全部出在**响应正文观测**（抓不到真实响应正文 / `has_audio` / ASR 回复），不是产品链路判错。**但那套验收脚本没有入库**（只在 `/tmp` 用过，已随会话消失），`17/3` 这个数字现在**无法复现，不应引作验收依据**。要长期保留这套验收，脚本得先入库。

**判定链路真跑了的强证据是「输入侧只有音频、输出与音频内容相关」**：浏览器只送 PCM 不送文字，回复相关就只能是 ASR + 模型的产物。断言里必须显式校验「文字字段为空」，否则测的是另一条路径。

### 4.2 signed 16-bit PCM 打包必须给高字节加 `&255`
`String.fromCharCode(v & 255, v >> 8)` 对**负样本**会抛 `RangeError` —— `>>` 是算术右移，-1000 右移 8 位仍是 -4。**任何含负样本的真实音频必然失败，只有纯静音「成功」**。正确写法 `(v >> 8) & 255`。更贵的教训是外层 `catch { return '' }` 把异常吞成空串，界面只显示「没录到声音」—— 打包类函数至少要 `console.error`。

### 4.3 「模型支持图片」必须用真实照片测，且要人工核对
纯色小图会被内容审核**静默剥离**，模型靠猜仍能答出一个像样的颜色词，看着像通了其实模型是瞎的；`base_resp.status_code=0` 同样不够（审核剥离也是 200 + 0）。**判定标准是「描述具体到画面位置且与原图一致」**。另：视觉必须走 `/v1/text/chatcompletion_v2`，`/v1/chat/completions` 带图一律 `2013 invalid params`（纯文本正常）—— 那是「路径不收图」，不是「模型不支持图」。

### 4.4 ASR 端点是下划线，不是斜杠
MiniMax 的 ASR 是 `POST /v1/speech_to_text`（下划线）；`/v1/speech/to/text`（斜杠）连同其它 10 条候选路径全部 404，一度误判成「服务商没有 ASR」。**路径 404 ≠ 服务商没有这个能力**，拿不准就去查官方文档。附：上游只收带容器的 wav/mp3，不收裸 PCM —— 网关侧统一封 WAV 头再上传，设备端仍只传裸 PCM。

### 4.5 电子书清洗：分水岭是「有没有文字层」，不是「用哪个库」
带文字层的中文 PDF，**pypdf 字符召回 100%、无空格污染、无乱码**，与 python-docx 同级；`.toc` 字节偏移全部准确落在章节标题开头。

**扫描件 PDF 两条路都是零字符** —— 清洗后为空文本，`clean_book` 如实抛「这份文件没有可提取的文字（可能是扫描图片版），需要另行识别后才能入库」。**零 AI 契约下这是正确行为，不是 bug**；要支持扫描件必须另开 OCR 能力。

PDF 比 DOCX 多约 3% 噪声（页脚「— 第 N 页 —」）。教材来源以 DOCX 为主时优先要 DOCX；PDF 路径建议在清洗阶段剥离页脚行。
