## SQLite 数据库（当前架构）

### 表结构

```sql
photos(id, filepath, date, timestamp, source, media_type, ai_desc, ai_tagged_at, created_at, updated_at)
tags(id, name, category, is_system, created_at, updated_at)
photo_tags(id, photo_id, tag_id, source, created_at)  -- source: 'ai' or 'user'
tag_aliases(id, tag_id, alias, created_at)
```

### 关键文件

| 文件 | 用途 |
|------|------|
| `gallery/db.py` | 数据库层（连接/初始化/CRUD） |
| `gallery/migrate_to_db.py` | 一次性迁移脚本（.meta → SQLite） |
| `gallery/app.py` | Flask 服务，标签读写走 DB |

### 数据现状（迁移完成时）

- 照片：33 张（全部已迁移入库）
- 标签：53 个（标准标签 51 + 新增 2：建筑、旅行）
- 标签关联：20 个（微信照片 AI 标签已入库）

### 设计决策

- `.meta` 文件**保留不动**（备份），cron job AI 标签和语义对齐仍写 .meta
- `app.py` 读 DB 为主，DB 无数据时从文件系统自动补充（upsert）
- 标签查询走 DB，不需要遍历文件，搜索提速 10-100x
- `set_photo_tags` 删除时**不分 source**，全部删掉再重新写入

## 完整流程（当前）

```
上传 → inbound/ → media-watcher（来源识别）→ .meta 写入 source
              ↓
         AI打标签（微信走 cron agent / 飞书走 organize.py）
              ↓
         inbound/ 有 ai_tags → organize.py 移动到 photos/
              ↓
         photos/{日期}/ + .thumbnails/
              ↓
         标签写入 gallery.db（迁移脚本一次性；AI打标签/用户编辑持续写入）
              ↓
         tag_align.py 语义对齐（每天 10/14/22 点，写入 .meta + DB）
              ↓
         app.py Flask 服务（读 DB）→ gallery.html / photo.html 展示
```
