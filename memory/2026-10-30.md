### fallback 不独立（关键结论）
`agents.defaults.model` = primary `minimax/MiniMax-M3.1-Flash`，fallbacks `['minimax/MiniMax-M3','minimax/MiniMax-M2.7','minimax-portal/MiniMax-M3']`。

### 13:30 心跳价值判断（冰河大人问「心跳有意义么？」）

结论：心跳有意义，但当前配置（30 分钟一轮 + 跑在 main session + 检查项多为恒定量）是净负的。

- 00:05–08:05 连着 17 轮 `status=ok`，正文是纯 `NO_REPLY` 的只有 4 轮（00:06 / 00:36 / 01:10 / 01:37），其余 13 轮都是 `All checks green — external 200, units active, failed count still the known 3…` 这种复述

1. **额度被巡检先花完**：30 分钟一轮 = 一天 48 次 agent turn，全吃 MiniMax Token Plan。11:05 与 12:20 两轮 `agent-runner-failure` 恰好发生在真正可能有事的时候——巡检把该留给真活的额度提前耗尽。

### 实测 token 用量与积累效应（16:14-16:25，修正此前所有估算）

数据源：~/.openclaw/agents/main/agent/openclaw-agent.sqlite 的 transcript_events（event_json.usage）。按 Flash 单价（input 0.1 / output 0.4 / cacheRead 0.02 美元每 M）折算。

- **全库 9 个有 usage 的会话共 33.6 USD ≈ 242 CNY**。此前我说「账单不是大钱」是错的。
- 成本构成：**缓存命中 54.4% + 未命中全价 input 41.8% + 输出仅 3.8%** → **96% 是上下文重发**。此前说「输出最贵」也错（输出只占 3.8%）。
- Top 4 会话占 95%：66d779e6=119 CNY / 7bfcd050=70 / 557bac30=23 / 1ed65453=19。
- **积累效应**：同一会话内每轮 cacheRead 随轮次增长——前 10 轮均 23.9k → 前 25 轮 51.5k → 前 100 轮 101k → 前 200 轮 130k（约 5.5 倍）。后半程每轮都在为前半程的历史付钱。
- **compaction 553 次**（cacheRead 崩塌点，3 个会话分别 170/360/23）→ 每次 = 一次全价模型调用 + 缓存重建。
- **会话分裂测算**（用同一会话前 N 轮的真实均值外推）：4727 轮实际 cacheRead 424M；拆成 25 轮一段 ≈ 243M（**省 43%**）；拆成 10 轮一段 ≈ 113M（**省 73%**）。
- **轮次放大**：66d779e6 会话里 481 条用户消息 → 4727 次模型调用 / 3824 次工具结果 ≈ **每条用户消息触发 ~10 次 API 调用、~8 次工具调用**。这是「无效检查」的量化画像。
