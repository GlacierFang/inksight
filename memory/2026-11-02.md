**决定性发现**：DCloud 官方 hello-uts 仓库的 `uts-nativepage` 插件**已有可运行的 AppWidget 实现**
（`DoAppWidget.uts` + manifest receiver + res）→ 本插件照抄官方写法。

**官方命名规则（查实）**：
- 包名 `io.dcloud.uni_modules.lp_widget`（插件 id 下划线化）
- 类引用 `uts.sdk.modules.lpWidget.LpWidgetProvider`（插件 id 驼峰）
- R 类 `io.dcloud.uni_modules.lp_widget.R`
- 类写在 `utssdk/app-android/index.uts`（官方 `DemoActivity` 就这么被 manifest 引用）

**产出**：
- `uni_modules/lp-widget/`（7 个文件：package.json / readme / index.uts / AndroidManifest.xml / 4 个 res）
- `utils/widget.js`（写 uid 文件 + Native.js 发刷新广播）
- `App.vue` onLaunch 调 `syncWidget(getUid())`

**几个刻意的设计**：
- 文字全在像素里 → widget 只有一个 ImageView，没有文字排版问题
- 裁切安全性是推理出来的：成品图 = 1080×1440 画面 + 文字带，`side = h*3/4 ≥ w` → 恒取顶部正方形，碰不到文字带
- uid 走**文件**不走 SharedPreferences，且 JS 侧**不 import 原生插件**（无编译期依赖，标准基座也不炸）
- ⛔ RemoteViews Bitmap 1MB IPC 上限 → inSampleSize=2 + 缩到 320px（约 409KB）
- 刷新节奏：系统 30 分钟一次 + App 打开时广播主动触发

**静态校验**：XML 5 个 minidom.parse 通过、JSON 通过、`node --check` 通过。
**未验证**：需要自定义基座（云打包）才有原生代码。冰河大人需在 HBuilderX 勾选 lp-widget 做自定义基座。
