**A. 05 §3.4 联调测试向量不可复现（硬伤，端云地基是坏的）**
用 `cryptography` 实现，先过 NIST SP800-38A F.5.1 官方向量自检，再核对文档 7 个断言 —— **全部不符**。
穷举 8 种 CTR 约定变体 + 20 种 HMAC 组合，无一命中。文档声称的 `block2 nonce = …0f12` **是对的**（IV 末字节 `0x10`+2=`0x12`），错的是它下面挂的**密文期望值** —— 说明是密文被凭空填写，而非实现约定分歧。
04 §4.2 还拿这条向量当强制单测依据，照着写必挂。
风险：有人为「让测试变绿」反向改实现，就会写出不自洽的端云协议。
→ 已用实测权威值替换整组向量，并加「向量生成与校验规范（强制）」四条（标准实现产出 / 先过 NIST 自检 / 配套脚本必跑 / **严禁反向改实现**）。

### ⚠️ 推翻的环境旧认知：pypi 实际可直连

旧记录（TOOLS.md 及多处 memory）称「pypi 不在出口白名单 → pip 装不了」。**这条只对走代理的链路成立。**
unset 代理变量后**直连 pypi.org 完全正常**：

```bash
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY -u all_proxy -u ALL_PROXY \
  python3 -m pip install fastapi pypdf     # 实测装成 fastapi 0.165.0 / starlette 1.10.0 / pypdf 7.1.1
```

→ 已修正 `AGENTS.md`「外网访问纪律」与「eink-mini 固件构建」两处表述。

**由此推出的真实原因**：eink-mini 装不上 PlatformIO，**不是 pypi 不可达**，而是 PlatformIO 的平台工具链源（`dl.espressif.com` 等）不在白名单 —— 此前归因错了。

**另外两个必须记住的坑**：
1. **PEP 668**：系统 Python 被标记 externally-managed，`pip install` 直接拒绝 → 用 `python3 -m venv --system-site-packages .venv`（复用已装的 uvicorn/httpx/cryptography/starlette）。
2. **loopback 也会被代理劫持**：进程继承代理环境变量时，`httpx` 访问 `127.0.0.1` 返回
   `403 Host "127.0.0.1" is not in the secret egress proxy traffic allowlist` → 本地自测客户端必须 `httpx.Client(trust_env=False)`。
   这个坑不显式处理，Phase 1 的 CLI 模拟器会全线 403。
