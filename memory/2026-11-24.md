**CI 里三个坑（都踩过）：**

1. **`git commit-tree -p` 的父提交必须是 commit 对象** —— 传空树会 fatal（`is not a valid 'commit' object'`）。推新分支时首次推送**不能带 `-p`**，有 BASE 才带。eink-mini 那份没暴露是因为它推的分支已存在。
2. **`actions/checkout` 的凭据挂在被检出分支的 ref 上** —— 推新分支（fw-bin / ci-logs）时那个 ref 不存在，推送无凭据。解法：显式用 `GITHUB_TOKEN` 拼 URL 推 —— `git push "https://x-access-token:${GITHUB_TOKEN}@github.com/${GITHUB_REPOSITORY}.git" ...`。
3. **本机拉不到 Actions 的 logs / artifacts** —— blob 存储被出口代理挡成 403，`gh api` 与 `curl` 全堵，read-guard 也会拦。**解法：CI 失败时把 build.log 提交到 `ci-logs` 分支，git 通道能通** —— 与 fw-bin 取固件产物是同一条思路。这条是本轮定位所有编译错误的关键手段。
