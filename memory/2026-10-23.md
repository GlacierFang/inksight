## 自定义模式「宋人日课」返工（2026-10-23 凌晨）

### 问题
用户反馈：无设备体验页连刷几次「宋人日课」，内容全是毕昇/活字印刷。

### 三个原因（都查实，非猜测）
1. **预览缓存 TTL = 5 分钟**，缓存键不含日期（`core/cache.py:194`）。WebApp 预览页不传 `no_cache=1`，5 分钟内返回同一张图（`X-Cache-Hit: 1`，字节相同）。
2. **无设备预览不做 LLM 去重**（`core/json_content.py:804`）：去重历史只在 `if mac and ...` 时加载，预览无 `mac`，模型看不到近期输出。
3. **prompt 题材引导偏置**：原 prompt 写死「活字印刷与《营造法模》」，模型易连续选同一题材。

### 我自己犯的错（已更正）
文档曾写「手写 `fallback_pool`，屏上内容永远不出错」——**错的**。
`fallback_pool` 只在 **LLM 调用失败**时才被 `_get_fallback()` 使用；LLM 成功时模型输出什么就渲染什么，池子不参与约束。
→ 已在 `memory/projects/InkSight-自定义模式开发.md` §2.2 更正并标注。

### 修法
`content.type` 从 `llm_json` 改为 **`static`** + `fallback_pool`（**不写 `static_data`**）：
`static` 取 `content_cfg.get("static_data", fallback)` → 落到 `fallback` → `fallback_pool` 的**随机一条**。
**全程不过 LLM**：内容 100% 手写可控，零幻觉、零成本、离线可跑。

池子从 10 条扩到 **27 条**（宋陵 4 / 名窑 8 / 科技 4 / 名画 2 / 城市 2 / 制度 3 / 人物 4）。

### 踩到的第二个坑
重写 JSON 时**漏了顶层 `layout` 块**，且把 `preset`/`preset_props` 误提到顶层 → 模式**校验失败、根本没注册**（服务日志 `[Registry] Validation failed`）。校验要求 `layout` 必须是对象并通过 `validate_layout_dsl`。
正确结构：`layout.layout_engine=component_tree` + `layout.body_preset=poetry_card` + `layout.preset_props{...}`。
**教训：改这个 JSON 只能整块替换 layout，不要凭印象重组字段。**

### 验收
- registry：`CUSTOM_SONG_LORE` source=`builtin_json`，总 31 模式
- 进程内连抽 12 次 → **12 个不同标题，12/12 全部在手写池内**
- 公网 preview `no_cache=1` 连 4 次 → 4 张不同 PNG，`X-Cache-Hit: 0`
- catalog 命中，`category="more"`

### 遗留
- 预览页没有「换一条」按钮（页面不传 `no_cache=1`）→ 5 分钟内刷不出变化。已向用户提方案。
- `static` + pool 是**随机**轮转，非「按日期确定性选取」。要做到「一天一屏、零点换」需加 computed provider 或用 `refreshInterval=1440` 近似。**待用户定。**
