# InkSight 狸行记（CUSTOM_MIAOLI）

## 一句话

喵狸的日漫一日。一次 LLM 写画面，一次生图出一张日漫图。屏上一句话都没有。

## 定位（2026-11-02 冰河大人定的）

冰河大人原话：「一个简单的给 prompt 出图的功能」「就是日漫，日漫！」

中间踩过的坑（都别再犯）：
- 第一版把「参考草地铺道蚁」读成了照抄草铺的版式 —— 屏上出现标题+四行正文+心声+状态
  那套文字模式，用户直接否掉：「这是日漫么？这是纯图片么？下面的文字是怎么回事？」
- 第二版自己加了对话气泡，理由是「日漫该有台词」。用户否掉：「不要对话不要气泡！」
- 第三版把草铺的参数（骰子、五档落点、状态轴、捡东西收集册）整个搬过来，
  变成「一只猫在执行我设计的旅行系统」。用户否掉：
  「我说参考草铺，是参考行为逻辑讲故事的方式，你把一堆参数也都拿过来了，这对么？」

结论：**草铺可以参考的是「行为逻辑讲故事的方式」，不是它的版式，更不是它的参数。**

## 屏上结构（照抄透屏）

- 状态栏隐藏
- 整版图 400×270 占满正文区（ART_DISPLAY = (400, 270)）
- 页脚「狸行记 | 喵狸·签名」（label + attribution_template）

## 版式：一格单幅（2026-11-02 冰河大人定）

**曾经是左右等宽双格，后来改成一格。**

改的原因（冰河大人原话）：
「如果这样，那就还不如用一格呢，两格的效果太差了」
—— 一次生图只能出一张图，两格塞进同一张里每格太小，猫画不清、动作也断。

早先的双格要求（左右等宽、中间粗黑竖线、左格起势右格爆发）**全部作废**。

## 屏上结构（照抄透屏）
- **出图时屏上没有任何文字块、没有气泡**（tests/test_miaoli.py::test_screen_has_no_body_text 守着这条）
- 没图时允许一句兜底提示「今日未画」（透屏的「未见电路」同理）

文字去哪了：
- 画面描述 → 只进生图 prompt + 回顾页画廊字段

## 生图提示词（2026-11-02 最终版）

    日漫风格，狸花猫。<LLM 写的动作>。画面只用四种颜色：纯白纸面底、
    墨黑 #000000 勾线、金黄 #E8B000 填色、朱红 #C80000 点缀。不要任何文字、印章、水印。

**结构是冰河大人定的**：前面是风格要求（固定），后面是 LLM 生成的动作。
风格和主体先读，模型才知道按什么画。

**只给风格要求。** 不限定猫的造型，不写角色锚点，不写动态表达 ——
那些交给模型。冰河大人原话：

> 「你只需要给风格要求不就好了，折腾这么多有的没的意义在哪里？」
> 「你限制的越多，出图的效果越差！」

**不要自己编风格词。** 「版画」「粗墨勾线」「网点纸」「大留白」全是我编的 ——
冰河大人从没说过这些，而且出图效果更差。风格就用他给的原话「日漫风格」。

**四色盘是屏幕物理事实，不是创作限制**：屏是四色
（core/config.py 的 EINK_4COLOR_PALETTE = 黑/白/金黄 #E8B000/朱红 #C80000），
写最短的一句就行。之前写「2 色屏」是我没查就写下的错假设，还被当成了禁用上色的理由。

**LLM 层**：DAY_PROMPT 要 LLM 写一个动作瞬间，用「它」不用「我」
（提示词开头已经有「狸花猫」，主语不能打架）。

## 名字固定

CAT_NAME = "喵狸"，不让模型自封（第一版模型自封「山大王」，用户定的名字不能被覆盖）。
模型只出：标题、画面、签名。

签名去重：页脚是「喵狸·签名」，模型偶尔会写「喵狸来此一爪」，
拼起来变成「喵狸·喵狸来此一爪」—— _strip_name() 去掉开头重复的猫名。

## 教训（2026-11-02 这一晚踩的坑）

**一、限制越多，出图越差。** 我给提示词加了一堆自认为对的约束：
角色设定（M 字纹/铜钱项圈）、造型限定（杏仁眼/尖下颌/细腰长腿）、
动态表达（速度线/集中线/斜切构图）、12 条否定清单。
每一层都是替模型做决定。全砍掉之后图立刻「舒服多了」。
**奥卡姆剃刀在提示词上同样成立。**

**二、不要把自己造的答案当成用户的要求。** 「版画」「粗墨勾线」「网点纸」「大留白」
是我从兄弟模式（天工阁/大宋梦影）和 UI 排版词汇里抄的，用户从没说过。
更糟的是我把「日漫 = 分格页 + 网点纸 + 大留白 + 斜切构图 + 速度线 + 角色画法」
写进了本文件，下一轮读回来当成用户口径继续用 —— 自己造的答案自己当依据，闭环了。
**风格词要么用用户原话，要么问，不要自己编译。**

**三、出图判断权在用户。** 我连着四张图自己看自己评（「双格和速度线出来了」、
「水印全对上了」），还据此加约束。用户：「我说了无数次了，出图我来判断。」
**出图只负责发，判断权交回去。**

**四、把图发给用户。** 我一直用 view_image 看到图，但那是私有上下文，
用户那边什么都收不到。用户：「图片你不发出来，我怎么判断？」
**看到图 ≠ 用户看到图 —— 必须用 MEDIA: 发出去。**

**五、屏是四色，不是两色。** 我没查就写「2 色屏」，还拿它当理由禁掉上色。
真相在 core/config.py 的 EINK_4COLOR_PALETTE（黑/白/金黄 #E8B000/朱红 #C80000）。
**技术事实先查再用，没查过的不要写进代码当依据。**

**六、参考兄弟模式要看对的那个。** 小景（core/xiaojing.py）和狸行记最像 ——
同样每天一张画、同样走 prepare_direct_art。读它能直接拿到：五段式提示词结构、
风格一句话就够、只做正面描述、重试只加一句。
我没读小景，反而抄了天工阁（展签图，本就该锁死）。
**「参考 X」要选同类的那个，不是名字好听的那个。**
