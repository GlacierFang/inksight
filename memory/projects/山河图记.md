## 一、战略升维（冰河大人 9:27 + 9:29 + 9:30 拍板）

### 1.1 真出路（9:27）
**地理探索工具 / 虚拟地理实验室**
**核心比喻**：让学生**像地理学家一样** —— 观察、提问、模拟、验证、记录
**不**是：刷题 / 单向讲解 / 考试导向

### 1.2 AI 角色根本性升级（9:29）
**AI 地理探究助手 = 苏格拉底式追问者**
**核心逻辑**：学生提出地理问题 → AI **不直接给答案** → 引导学生自己找到答案

**强对位**：
- 2025 课标"问题式教学"（"问题—情境—任务"）
- "结构不良情境"训练（4→3 级评价关键依据）
- 5 步法中"提问·模拟·验证"3 步**全部**对位

**冰河大人示例**（强示范）：
> 学生："为什么郑州 2025 年夏天这么热？"
> AI："要理解这个问题，我们可以先看看郑州 7 月的气温数据，再对比一下同纬度其他城市。你觉得可能和哪些因素有关？地形？城市规模？大气环流？"
> 学生："可能是城市热岛？"
> AI："有可能。那你能在 App 里叠加一下郑州的土地利用图和气温分布图，看看高温区域和建成区是否重合？另外，2025 年副热带高压的位置有没有异常？你可以调出 500hPa 高度场数据看看。"

**关键**：AI 角色 = 引导探究，**不是**给结论。

## 十三、闭环深度阐释与设计哲学（冰河大人 10:09 原话沉淀）

> 冰河大人 10:09 原话（**一字不差**，**不**做加工，code block 包裹保字）：

```
第一步：知识卡片化（拆解）
把地理知识拆成一张张独立的碎片卡片。卡片的内容是不变的知识点（原理、规律、概念），大章节就是这些卡片的集合。
第二步：AI预生成讲解（输入）
每张卡片配上AI生成的精准讲解，保证知识传递的准确性和效率。
第三步：拍照任务与落库（输出与实践）
学习完卡片后，布置拍照任务。这里你抓住了地理的灵魂——地理实践力。
重点在于：
1. 有选择地布置：太阳系确实没法拍照（笑），但地形地貌、河流侵蚀、城市功能区、农业生产景观，这些完全可以让学生在生活中拍。
2. 落库与分析：拍照结果要入库，并且和关联知识进行比对分析。这比单纯的"打卡"高级太多了，AI可以基于照片里的真实场景，反过来印证卡片上的原理。
第四步：章节对话与打分（考核）
一个大章节学完+任务做完，进入AI提问对答环节。
限制对话次数（防止变成漫无目的的闲聊），根据回答打分。超过分数线，视为该大章节"通关"。这是一种典型的游戏化机制，有明确的成功判定。
第五步：研学任务（综合应用）
通关后，布置研学任务，由学生自己完成，最终生成报告。这是从"被动接收"走向"主动探究"的关键一步。
第六步：知识图谱解锁（网络构建）
每学完一个大章节，解锁对应的知识图谱关联。
这太聪明了。地理知识本来就是纵横交错的。一开始是孤立的卡片，随着进度推进，图谱逐渐亮起，最终形成一个巨大的、可随时回看、随时调用的地理知识网络。
为什么这个设计特别符合地理学科的本质？
- 它呼应了我们刚才的共识：卡片承载不变的地理原理（骨架），而学生自己去收集的数据、拍下的照片，是长在上面的血肉。学生不是背数据，而是用自己收集的现实素材来验证原理。
- 它把"AI"用在了刀刃上：AI负责高质量的讲解生成、照片的对比分析、对话评分。AI不是替学生思考，而是充当导师和陪练。
- 知识图谱是终极壁垒：碎片化学习最怕"只见树木不见森林"。你的机制是从碎片出发，最终在图上连线成网，让学生真正拥有全局观和综合思维。
```

**现在**：4 层防御真有效

```css
/* 1. page { touch-action: pan-y } = 安卓关键 */
page { touch-action: pan-y; -webkit-overflow-scrolling: touch; }

/* 2. page { overflow: hidden } = body 锁死 */
page { height: 100%; overflow: hidden; }

/* 3. html, body 双保险 */
html, body { height: 100%; overflow: hidden; overscroll-behavior-y: none; }

/* 4. * { overscroll-behavior: none } = 截断子元素链 */
* { overscroll-behavior: none; }
```

**为什么之前 3 层不工作**：
- `overscroll-behavior` 在安卓 WebView 7.0+ 才支持 = 概率性失效
- **没** `touch-action` = 安卓浏览器**仍**尝试原生 overscroll
- `html, body` 在 uniapp nvue/native 上下文可能**不**生效

**真防橡皮筋的 2 个关键**：
1. **`touch-action: pan-y`** 限制浏览器**只**处理垂直 pan = 不触发原生 overscroll
2. **`<scroll-view>` 元素**（uniapp 标准做法）= 内容滚动靠 scroll-view，不靠 body 滚动 = 没机会抖
