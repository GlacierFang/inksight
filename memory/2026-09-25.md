## 上午：水豚发呆轮播图批量处理

**任务**：48 张 16:9 水豚 watercolor → 透明 PNG → 144×198 (2x retina) → 72:99 比例

**前置**：用户已把 JPG 转成透明 PNG（仍是 1280×720）

### 算法

```python
1. PIL 加载 + RGBA 模式确认
2. alpha 通道 bbox 检测（getbbox()）
3. 中心裁切到 72:99 比例（ratio=72/99=0.727）
4. 加 10% padding 呼吸空间
5. LANCZOS 重采样到 144×198
```

### 批处理结果

- 48 张全部成功
- 输出尺寸全部 144×198 (2x retina)
- 文件大小 39-46KB / 张

## 新 SOUL.md 工作纪律（今天写入）

**#4.5 edit 后必 diff 备份（避免误伤）**：
- 报告"完成"前必须 `diff <备份文件> <当前文件>`
- 逐 hunk 检查，**只允许预期行被改动**
- 任何意外 diff → **立刻停手排查**
- 理由：grep 能验证"改的对"，但验证不了"没改错其他"。diff 才是"只动了预期"的唯一真相源

**#11 渲染异常先排查缓存**：
- 代码对但显示 undefined / 空白 → 先怀疑 HBuilderX / stale build 缓存
- 不要陷在代码里钻，要求完全关闭 App + 清缓存 + 重新打包
- 验证时间 5 分钟 vs 钻代码半小时，前者更值得先试
